## DIF-27.1-1：CI K3.3 第 13 行断言与 root-task supervisor 语义代差

- **蓝图坐标**：§5.3「CI 既有 13 行启动断言复现」。
- **实测**：2026-08-10 qemu-prod 复现 12/13；缺 `[eneros-root-task] svc-fault
  suspended (isolated)`。当前 root-task 的故障处理语义为 **fault → 检测 →
  restart in 1000ms → restarted (total=N)**（`target/wp271-evidence/qemu-serial.log:866`），
  故障隔离闭环由 `svc-hello still responsive` 与 fault 计数维持。
- **先例**：G1 日志（2026-08-09 21:31）同样缺该行——断言与代码的偏差**先于
  本 WP 存在**，非本 WP 引入。
- **处置**：不改 CI 断言（测试纪律：禁改断言迁就实现）；登记待 WP-27.9 目标侧
  测试（K3.3 序列门随 root-task 语义更新为 restart 形态）处理。

## DIF-27.1-2：蓝图 §5.1 H1 假设（固件代差）与事实不符

- **蓝图假设**：UEFI 2025.11 写入的 BOOTCTRL 布局与 2024.02 不同。
- **实测**：BOOTCTRL 分区由 xtask 镜像工厂与 boot-manager 自身写入，UEFI 固件
  不写该分区；2025.11 固件（2025.11-3ubuntu7）下 G1 日志完整复现启动序列。
  根因定性为 **H3（工具/状态管理）**：同盘重跑（cache=none 直写 → seq=1）
  + 每次全新 VARS（无锚点）→ fail-closed Genesis；`reset-bootctrl.py` CRC
  缺最终异或导致归零副本 decode 失败。
- **处置**：H1/H2 排除结论 + 真实字节证据入 `evidence/boot-unblock/`；
  AAVMF 锁定声明见 `docs/boot/aavmf-firmware-lock.md`。

## DIF-27.1-3：qemu-prod Expected::Pass 与 seL4 无 ACPI 关机的既有张力

- **实测**：seL4 无 ACPI 关机 → QEMU 200s 超时 kill（exit=124）→ xtask 报
  FAIL → 超时分支提前返回，`bootctrl-state.json` 等证据不落盘；CI 以
  `|| test -s qemu-serial.log` 容忍后由 K3.3 门判定（ci.yml:360 注释同述）。
- **处置**：属既有设计，不属本 WP 范围；本 WP 证据用手动导出字节
  （`bootctrl-post-run-copy1.bin`）补足运行后 BOOTCTRL 状态。
