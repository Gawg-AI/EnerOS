# VRF-002：双构建字节比对门禁（S5）

## 实现

- xtask 命令 `cargo xtask build-compare`：两个**隔离构建环境**
  （不同 `CARGO_TARGET_DIR`：target/compare-a 与 target/compare-b）各自
  完整构建同一未签名 payload `eneros-hello`（纯 Rust，不依赖 sel4 链，
  sandbox 可复算），比对产物 sha256 与字节长度。
- 已纳入 CI：`.github/workflows/ci.yml` g0-fail-closed job 尾部步骤
  `VRF-002 dual-build byte comparison`。

## 执行记录（2026-08-05）

```
BUILD_COMPARE payload=eneros-hello env_a=target/compare-a env_b=target/compare-b
  sha256_a=effa4261b7f86fe98d2da78762a801db3f2a3757b0e4ed7e4924f06bd7de60ed
  sha256_b=effa4261b7f86fe98d2da78762a801db3f2a3757b0e4ed7e4924f06bd7de60ed
  len_a=300928 len_b=300928
BUILD_COMPARE result=PASS bit-identical
```

## 边界

- payload 选择：firmware-agent 依赖链在 release 被 Mock 封印（compile_error!
  安全门禁）拦截——改用 eneros-hello（未签名 payload，同确定性构建语义）；
- CI 全 profile 扩展由同一命令在 CI 环境复跑（含 sel4 链）。
