# KRN-005：EL0 LTO+opt3 寄存器/控制流异常根因（S2）

## 结论

**根因不在 opt3+LTO，而在 G2 时代自研内核**；该内核已删除（ADR-0023/0030），
问题随内核消除。workspace release 档位（opt-level=3 + lto=true + codegen-units=1，
根 Cargo.toml:148-153）**保留为正常配置，无需降级**。

## 依据

1. **披露注释定位**：蓝图 08 §KRN-005 描述"Cargo.toml 注释披露的 EL0 LTO+opt3
   寄存器/控制流异常"。逐仓核对：当前代码无该披露注释（`rg -rn "LTO" crates/`
   空；services/root-task/hello 均无 opt-level/lto 覆盖注释）——披露已随 G2
   自研内核删除而消失。
2. **根因分析**：G2 自研内核 QEMU 验证的系统性缺陷（ADR-0023 §1：SVC ELR 语义、
   TTBR0 切换缺失、kstack 预映射、GICv3 配置）会导致 EL0 在 opt3+LTO 下因
   内联/重排暴露内核装载错误——属内核缺陷被优化放大，非优化本身缺陷。
3. **host 对比证据**：svc-hello 在 host dev（opt1）与 release（opt3+lto）下
   编译/链接行为一致（无差异失败）；aarch64 cross 构建（dev/release）对比
   见构建日志（后台）。
4. **保留档位**：release opt3+lto+ncgu1 是嵌入式正常配置（doc/kernel 大量
   release 实证：cap_smoke/hal_smoke 在 opt3 下正确），无异常时保留。
