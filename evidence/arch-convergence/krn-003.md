# KRN-003：双 EL0 进程 IPC 往返 / 地址空间隔离 / 故障不扩散（S2）

## 状态

代码侧完成（host 可测），QEMU 运行验证 **BLOCKED**（sandbox 无 QEMU + seL4 构建链缓存缺失，见 KRN-006）。

## 代码侧交付（host 验证）

1. **IPC 帧往返**：`crates/abi/ipc-wire/src/el0.rs`（KRN-002 上移共享）——
   `encode_frame`/`decode_frame`（magic "E0FR" + type + len + crc32 尾）；
   root-task（`frame::*` re-export）与 services（`svc_frame_roundtrip`）共用同一帧格式。
   测试：ipc-wire 9 + services 2（roundtrip / 坏 crc 拒绝）。
2. **双 EL0 服务 ELF**：services crate 4 个 EL0 进程（svc-hello/pi/hog/fault）均为
   合法 aarch64-unknown-none ELF（`_start` loop），经 eneros-elf-loader W^X 校验后
   由 root-task spawn（M2.1 seL4 TCB/CSpace/VSpace FFI）。
3. **地址空间隔离**：seL4 语义——每个 EL0 服务独立 VSpace + TCB；root-task 仅持
   spawn 所需 capability（MASTER §G6 无捷径：Box<dyn AgentEntry> 不算 spawn）。
   QEMU 验证（两进程地址互不可见）BLOCKED。
4. **故障不扩散**：svc-fault 为故障注入参考服务；seL4 内核在服务 fault（SVC/异常）时
   接管并将故障转发给 root-task（IPC fault handler），不拖垮其他 EL0 服务。
   QEMU 验证（svc-fault 崩溃后 svc-hello 存活）BLOCKED。

## KRN-004：root-task 服务化 + config 服务接入运行时闭包

- root-task 服务化：`service.rs`（dispatch_frame：Ready/Report/Control 分发 +
  config_service_roundtrip），_start 不再裸 spin loop（4 host 测试）。
- 运行时闭包引用关系核对（消除孤立 library）：
  - `eneros-runtime`（no_std 串口/初始化）：被 hello/root-task 引用 —— 非孤立；
  - `eneros-config`（ConfigStore）：被 prompt-template / tsn-time 引用 —— 非孤立；
  - 衔接：root-task 的 config 服务接入点（Report 帧）在 M2.1 后由 runtime 层
    EL0 config 服务承载真实 ConfigStore（root-task no_std 不能直接依赖 std config，
    故以帧服务形态接入——与 07 蓝图「config 为独立服务」一致）。
- QEMU 端到端（root-task 真实 spawn + config 服务读写）BLOCKED（同 KRN-003 解锁条件）。
