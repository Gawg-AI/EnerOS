### 未列出的新增断裂面（全仓扫描登记）

1. **`ProtocolManager::write_point`（manager.rs:71-87）**：PointAccess 去写化后编译断裂。全仓无生产调用方（仅 lib.rs 测试 T12 使用）。处置：**移除**（旁路形态，D1 推论 C 的题中之义），T12 写断言随之改写。
2. **control-gateway 内部 `AuthorizedCommand` 消费**：`policy.rs:148`（`lease.devices.contains(&cmd.device_id)`，Vec<u32> vs u16）、`policy.rs:163`（同，rule.devices）、`safety.rs:122`（`(cmd.device_id, cmd.point_id)` 作 (u32,u32) key）、`gateway.rs:234`（authorize 构造点）。处置：`u16::try_from` 转换（越界→新 `GatewayError::BadDeviceId`，default-deny）+ 比较点 `as u32` 无损加宽。
3. **telemetry-model 承载位移**：依赖方向约束（见下）要求 `AuthorizedCommand`/`ActorKind` 落位共享模型层。control-gateway re-export 保持全部既有导入路径（`eneros_control_gateway::{AuthorizedCommand, ...}`、`crate::envelope::ActorKind`）。
4. **protocol-abstract 内部测试**：lib.rs T3（写点更新）、T12（跨协议写）、`write_points_batch` 测试——写路径随 D1 移除/改写。
5. **device-agent 测试 T20**：断言"匿名命令被执行落写"——正是本规格判定为**错误**的旧行为（§6.2 双轨：收到不执行）。测试改为断言"不落写 + 拒绝计数 +1"（防回归测试证明旧行为错）。

## 二、依赖方向检查（grep 证据）

```
$ grep -A5 '\[dependencies\]' crates/protocols/protocol-abstract/Cargo.toml
eneros-upa-model = { path = "../upa-model" }          ← 本 WP 后追加 eneros-telemetry-model（向下，非反向）
$ grep -A5 '\[dependencies\]' crates/protocols/control-gateway/Cargo.toml
eneros-crypto = { path = "../../security/crypto" }
eneros-telemetry-model = { path = "../telemetry-model" }   ← 无 protocol-abstract 依赖
```

- **protocol-abstract 不反向依赖 control-gateway**（本 WP 新增依赖仅 `telemetry-model`，而 telemetry-model 仅依赖 upa-model，方向向下，不构成"反向"）；
- **control-gateway 不依赖 protocol-abstract**（保持）；
- **upa-model 保持零依赖叶节点**（不动）。
- 落点推导：`AuthorizedCommand` 含 `ControlCommand`（telemetry-model::command 定义）→ 随 `ActorKind` 一并下移 telemetry-model::command 是唯一不破坏三 crate 依赖方向的方案（upa-model 为叶节点无法承载 ControlCommand）。

## 四、规格与代码现实差异记录（交付说明引用）

1. **AuthorizedCommand 落位**：规格 §6.1 契约套件假设 seam 层可直接引用 AuthorizedCommand；代码现实中其位于 control-gateway，protocol-abstract 引用即构成 §7.3 禁用的反向依赖。处置：下移 telemetry-model（含 ActorKind），control-gateway re-export，全部既有导入路径不变，零行为变化。→ 影响 telemetry-model 与 control-gateway 两个规格未列"直接修改"的 crate（D4 涟漪），已在 WP-24.1 侦察登记。
2. **protocol-sdk 示例**：规格 §2.2 预期示例编译失败；代码现实 SDK 独立于 seam，无断裂，按以代码为准不动。
3. **从站侧"明确不碰"**：D4 类型化迫使 3 行机械 cast 修复（handler.rs×2、slave.rs×1），default-deny 行为与匹配逻辑零变更，git 证据仅限这几行。
4. **§6.1 断裂面清单遗漏项**：ProtocolManager::write_point（移除）、protocol-abstract 内部测试、device-agent registry.rs MockPointDevice——已在清点表中登记处置。
