## 3. 本 WP 修复根因（QEMU 实弹逐轮定位，全部测试先行）

**1. 协议 NIC 槽位 mmio 虚拟地址冲突（spawn.rs，二修根因）**
- 现象：svc-goose(槽1,页0) 与 svc-iec104(槽9,页1) 的 mmio 基址都映射到
  `NET_MMIO_VADDR=0x40020000`、页内槽偏移 `&0xfff` 又都落在 `0x200` → 两服务
  vaddr `0x40020200` 重合（QEMU 实弹两服务 `[net] netstack-built mmio=0x40020200`），
  后映射者遮蔽先者物理帧 → iec104 virtio RX 失效。
- 修复：页 0 服务映射基 `NET_MMIO_VADDR`、页 1 服务映射基 `NET_MMIO_VADDR+0x1000`；
  `mmio_vaddr = 基 + 全量区域槽偏移`（唯一）。回归测试
  `net_mmio_vaddr_unique_across_all_slots`（100/100）。
- 修正后实弹：`NET-HANDOVER svc-iec104: mmio phys=0xa001200 -> vaddr=0x40021000`，
  netstack-built vaddr 全互异（0x40021a00/0x40020200/0x40021600/0x40021400/0x40021200/0x40021000）。

**2. config-bundle.bin 陈旧（poll_interval 未生效）**
- 现象：`[iec104-config] poll_interval_ms = 30000`（改 toml 未重建 bundle）。
- 修复：`cargo xtask config compile --profile qemu-prod --root-key-hex "$(printf '5a%.0s' {1..64})"`
  重建签名 bundle（pubkey 不变=svc-config 验签通过）；`product/config-bundle.bin`
  为非跟踪构建产物，不入库。此后 `poll_interval_ms = 5000` 落到运行行为。

**3. `poll_interval_ms` 未真消费（iec104-master adapter 硬编码 30_000）**
- adapter `start/poll_device` 里 `RemoteDevice::new(…, 30_000)` 写死，MasterConfig
  的 `poll_interval_ms` 解析后不落运行路径（46.3 "配置字段必须落到运行行为" 缺口）。
- 修复：`Iec104Adapter` 持 `poll_interval_ms`（来自 MasterConfig），start/poll_device
  统一使用。configs/protocol-iec104.toml `poll_interval_ms=5000`（对端读取窗口 20s）。

**4. 总召唤调度时钟域混用（iec104-master plugin poll）**
- 现象：connect 用 `transport.now_ms()`（= eneros_time 服务内小时钟），plugin.poll
  把服务侧大时钟（boot 相对）传给 `master.poll` → 调度首轮（STARTDT_CON 未消费）
  触发一次 StateError 后 `update_next(大时钟+5s)` 永不再次到期 → 总召唤不发。
- 修复：plugin.poll 一律用传输同源时钟 `eneros_time::get_monotonic_ns()/1e6` 传
  `adapter.poll`；`last_poll_ms` 保留调用方 now_ms（健康观测，host 测试语义不变）。
  诊断观测（自检窗口）：`conns=[Connected] sched=1:next=32414 int=30000` →
  修复后 `int=5000`、`conns=[Interrogating]` 状态迁移可见。

**5. TCP 流式粘包重组（StreamMasterTransport）**
- 现象：`TcpStreamHandle::recv` 返回字节流任意切片（STARTDT_CON `68 04 0B 00 00 00`
  被切成 5+1），`Box<dyn TransportHandle>` 直接实现 MasterTransport 把半帧交给
  process_rx 解码 `InvalidFrame` → 停在 StartDtPending（QEMU 实弹 `tcp-recv 104-frame
  n=5`）。
- 修复：`StreamMasterTransport` wrapper 累积到完整 APDU（`68 len` + 4B 控制 + ASDU）
  才返回，粘包余量保留下次；非 0x68 打头丢弃首字节防无限累积。回归测试
  `stream_transport_assembles_partial_apdu`（72/72）。

**6. 对端 u_frame 畸形（iec104_slave.py 独立对端）**
- 现象：`struct.pack(">BBBBB", 0x68, 0x04, func, 0, 0)` 只打包 5 字节；规范 IEC
  60870-5-104 U 帧 = `68 04` + **4** 控制字节（6 字节）。主站 decode 读 ctrl[0..4]
  正确拒收 → 停在 StartDtPending。
- 修复：`u_frame` 改 `>BBBBBB`（6 字节）。主站拒收畸形帧属正确行为，不改协议语义
  （断言漂移红线）；修对端帧。

**7. MMS 数据面对端事务（svc-mms 服务侧 Read 驱动）**
- MMS 插件为请求驱动（`client_mut` 由集成层发起 Read/Write，模块文档明示）；
  此前 svc-mms 用 `EmptyPointRegistry` → 关联（COTP+ACSE）后无数据面事务。
- 修复：svc-mms 经 `fetch_points_registry` 取点表（46.3 机制），关联建立后对 MMS
  映射对象引用发起一次 Read（`drive_mms_read`）→ 独立对端回 Read-Response 闭环。
  插件契约不动。
