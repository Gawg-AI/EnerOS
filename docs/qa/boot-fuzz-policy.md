# Boot parser mutation and fuzz policy

G1 parsers are allocation-bounded and have deterministic mutation suites for BootInfo, release/install manifests, measurement logs, BOOTCTRL and GPT. The suites cover every encoded byte where practical plus truncation, length overflow, reserved fields, CRC, duplicate/order, overlap, permission, load range and signature changes.

A parser panic, out-of-bounds access, unbounded allocation, timeout or acceptance of a non-canonical encoding is a FAIL. Empty corpora, ignored tests and quarantined crashes are not PASS. Seed corpus files are canonical golden encodings generated by the protocol tests; mutation cases are derived deterministically rather than by a fixed production RNG.

The current bounded suites run through `cargo test -p eneros-boot-protocol -p eneros-image-format -p eneros-boot-manager-uefi`. Long-running coverage-guided fuzzing and coverage retention can extend this corpus, but cannot weaken the deterministic Gate cases.
