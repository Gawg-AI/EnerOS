# D1 缺陷纪律（真机浸泡缺陷处置规程）

> 依据：蓝图/14-阶段D-商用验收闸门.md D1「缺陷纪律」。
> 版本：v0.255.0（RC-1c，D1 收口）。

## 1. 缺陷分级

浸泡（真机 72h 或 QEMU soak-run 循环）发现的缺陷按影响重新定级：

| 级别 | 判据 | 处置 |
|---|---|---|
| **P0** | 数据丢失/损坏、安全绕过、启动链失败、失联（协议 72h 断链） | **立即修复**，修复后**重启 72h 计时**；重启前必须完成根因分析并留档 |
| **P1** | 功能异常但可降级运行（如单点遥测丢失、调度次优）、性能退化超阈值 | 当轮修复或排入下轮 RC；不得携带进入 v1.0.0 |
| **P2** | 非功能瑕疵（日志缺失、指标偏差、文档失实） | 记录缺陷清单，阶段内择机修复；v1.0.0 闸门 G1 要求清零 |

## 2. 缺陷处置流程

1. **证据固定**：缺陷复现输入（串口日志片段/断电时序/抓包）立即归档至
   `target/soak/evidence-bundle/`（经 `tests/soak/collect-evidence.sh` 打包，
   含 sha256 清单）。
2. **根因分析**：P0 缺陷 24h 内给出根因结论（引用代码 文件:行号），
   附防回归测试（证明旧行为错误、新行为正确）。
3. **修复闭环**：P0 修复 → 防回归测试绿 → 重启 72h 浸泡计时 → 浸泡通过
   后 P0 才算闭合。
4. **缺陷登记**：全部缺陷（含 P2）登记至 `docs/phase-d-defect-log.md`
   （表格：ID/级别/现象/根因/修复版本/防回归测试/状态）。

## 3. 浸泡失败判定

- 72h 内任何未解释重启（`restarts[].root_cause == None`）→ 浸泡失败；
- 数据腐化（`data_corruption == true`）→ 浸泡失败；
- 断电恢复校验任一次不一致 → 浸泡失败；
- 协议 72h 无失联期间任何断链且未自动恢复 → 浸泡失败。

失败后：按第 2 节流程修复 → 重启计时。连续 3 次失败 → 升级至架构评审。

## 4. 本环境（无真机）的执行口径

本仓库开发环境无飞腾/鲲鹏硬件与真实对端设备，D1 浸泡按三层口径执行：

| 层 | 内容 | 本环境证据 |
|---|---|---|
| 第一层 | 浸泡基础设施（脚本/门禁/报告） | ✅ 已交付（v0.253.0~v0.255.0）：soak72.sh、collect-evidence.sh、soak-run、soak-report |
| 第二层 | QEMU 浸泡循环（CI 可自动跑） | `xtask qa soak-run --cycles N`（CI 环境执行，本机无 QEMU） |
| 第三层 | 真机 72h 浸泡 | BLOCKED（缺硬件）；跳过证据+就绪清单已可产出（soak-skip-evidence.json） |
